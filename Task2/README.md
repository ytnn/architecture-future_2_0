# Задание 2. Разделение системы на домены и моделирование потоков данных для поддержки ключевых бизнес-сценариев

## Разделение системы на домены

| Домен                         | Что входит (по схеме)                                     | Ответственность                                                                                     | Какие сценарии поддерживает                                                                                           |
| ----------------------------- | --------------------------------------------------------- | --------------------------------------------------------------------------------------------------- | --------------------------------------------------------------------------------------------------------------------- |
| **Clinical Domain**           | Clinical Services, Clinical Database, AI Services         | Все медицинские процессы: приём, лечение, медкарты, вызов ИИ-моделей                                | Работа клиник, источник медданных для аналитики и ИИ                                                                  |
| **Fintech / Banking Domain**  | Core Banking (Postgres)                                   | Счета, транзакции, кредиты, финуслуги                                                               | Финтех-сервисы, продукты банка, сценарий «новый финтех-сервис»                                                        |
| **Data Platform (Lakehouse)** | Data Lakehouse, Semantic Layer                            | Сбор CDC/событий из доменов и Legacy DWH, хранение Bronze/Silver/Gold, формирование витрин и метрик | Быстрая подготовка отчётности, единая витрина данных, обезличенные выборки для ИИ                                     |
| **Data Portal & BI**          | Data Portal, BI Platform                                  | Self-service доступ к витринам, построение отчётов, регуляторная отчётность                         | Самообслуживание по данным, отчёты для менеджмента и регуляторов                                                      |
| **Integration Layer**         | API Gateway, Kafka Event Bus                              | Единая точка входа для партнёров и фронтов, маршрутизация и потоковая интеграция между доменами     | Интеграция новых партнёров (финтех, фарма, электроника), обмен событиями между клиникой, финтехом и платформой данных |
| **Security (IAM / SSO)**      | IAM / SSO                                                 | Аутентификация, авторизация, RLS/CLS для BI и портала                                               | Безопасный доступ к мед- и финданным, соответствие требованиям регуляторов                                            |
| **Legacy Systems**            | Legacy DWH (SQL Server 2008)                              | Историческая отчётность, источник данных для миграции в Lakehouse                                   | Временная поддержка старых отчётов до полной миграции                                                                 |
| **Партнёрские системы**       | Фармкомпании, производители оборудования, финтех-партнёры | Внешние поставщики медданных, телеметрии, платёжных сервисов                                        | Подключение новых бизнес-направлений к экосистеме «Будущее 2.0»                                                       |




## Аргументация логики разделения на домены

| Причина разделения                                                                            | Что даёт бизнесу                                                               |
| --------------------------------------------------------------------------------------------- | ------------------------------------------------------------------------------ |
| **Домены отделены и взаимодействуют через Integration Layer и Data Platform**                 | Независимое развитие клиники, финтеха и ИИ без доработок в DWH                 |
| **Клиника и финтех публикуют события и CDC-потоки в Data Platform**                           | Ускорение вывода продуктов: изменения в домене не требуют модификации общей БД |
| **Data Platform формирует витрины и метрики, а не DWH**                                       | Быстрая отчётность и единая витрина данных для всех направлений                |
| **ИИ получает обезличенные данные из Lakehouse, а результаты возвращаются в Clinical Domain** | Безопасное использование ИИ без влияния на продуктивные системы                |
| **Legacy DWH вынесен в отдельный домен**                                                      | Снижение зависимости от устаревшего DWH, возможность постепенной миграции      |
| **Integration Layer принимает внешних партнёров (фарма, электроника, финтех)**                | Масштабируемость экосистемы и быстрый onboarding новых сервисов                |
