# Задание 1. Проектирование целевой архитектуры и приоритизация проблем для поддержки ключевых бизнес-сценариев компании

## Проблемные места

| Проблема                                                        | Как проявляется                                          | На что влияет                             |
| --------------------------------------------------------------- | -------------------------------------------------------- | ----------------------------------------- |
| **Монолитный DWH на SQL Server 2008 медленный и перегруженный** | Отчёты считаются часами                                  | Быстрая подготовка отчётности         |
| **Логика и интеграции зашиты в DWH**                            | Любые изменения ломают отчёты и ETL                      | Независимое развитие доменов          |
| **Клиника, финтех и ИИ связаны через общий DWH**                | Сильная связанность, сложно менять независимые части     | Независимое развитие доменов          |
| **Нет облачной платформы данных**                               | Не хватает масштабируемости и гибкости                   | Масштабирование под новые бизнесы     |
| **Нет потоковой передачи данных (Kafka)**                | Данные приходят с задержками                             | Отчётность, масштабирование       |
| **Нет портала самообслуживания**                                | Пользователи ждут ручных выгрузок                        | Быстрая отчётность                    |
| **Нет IAM/SSO, доступы разрознены**                             | Риски безопасности, ручное управление правами            | Развитие доменов,масштабирование |
| **Старая интеграционная шина Camel**                            | Медленные интеграции, сложно подключать партнеров        | Масштабирование бизнеса               |
| **Legacy DWH нельзя быстро отключить**                          | Риски миграции, необходимость временного сосуществования | Все сценарии косвенно                 |



## Приоритизиация проблем MoSCoW

| Проблема                                               | Приоритет                | Причина (привязка к бизнес-целям)                                        |
| ------------------------------------------------------ | ------------------------ | ------------------------------------------------------------------------ |
| **Монолитный и медленный DWH на SQL Server 2008**      | **MUST**                 | Критично для быстрой подготовки отчётности — отчёты считаются часами |
| **Логика и интеграции «зашиты» в DWH**                 | **MUST**                 | Блокирует независимое развитие доменов (клиника, финтех, ИИ)         |
| **Клиника, финтех и ИИ связаны между собой через DWH** | **MUST**                 | Домены не могут развиваться отдельно, растёт time-to-market              |
| **Нет облачной платформы данных**                      | **MUST**                 | Невозможно масштабировать систему для новых бизнес-направлений       |
| **Нет потоковой передачи данных (Kafka)**              | **MUST**                 | Замедляет обновление данных и мешает подключать новые сервисы            |
| **Нет портала самообслуживания (self-service)**        | **SHOULD**               | Увеличивает нагрузку на IT, замедляет получение отчётов                  |
| **Разрозненная авторизация, нет IAM/SSO**              | **SHOULD**               | Важно для безопасности и масштабируемости; требуется для регуляторов     |
| **Устаревшая интеграционная шина (Camel)**             | **SHOULD**               | Усложняет интеграцию новых партнёров и направлений                       |
| **Legacy DWH нельзя быстро отключить**                 | **WON’T**                | Высокие миграционные риски, логично оставить в режиме read-only          |
